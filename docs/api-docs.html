API Docs

Use Deep Safety immediately.

Deep Safety exposes one consistent contract across the Python package, HTTP API, MCP bridge, and browser-local runtime. The endpoints below are designed to be application-ready and agent-friendly.

HTTP runtime

Deploy FastAPI with Docker or your own host and call the REST endpoints directly.

Browser-local runtime

Use `browser://local` in the site or call the browser adapter to run calculations client-side.

Agent surface

The MCP server wraps the same API so agents can discover models and run calculations safely.

Quick Start

Three common ways to work with Deep Safety.

# Python package
pip install deepsafety

from deepsafety import DeepSafetyClient
client = DeepSafetyClient("http://127.0.0.1:8000")
catalog = client.get_service_catalog()
// Browser-local runtime
const result = await window.DeepSafetyBrowserApi.request(
  "POST",
  "/effect-models/solve",
  {
    model_type: "thermal_probit",
    inputs: { heat_flux_kw_m2: 12.5, exposure_time_s: 30 }
  }
);

Core Endpoints

These are the main surfaces applications usually integrate first.

Endpoint Purpose Key payload fields
GET /models Discover available implemented and planned models. include_planned
GET /models/{model_id} Inspect equations, constants, inputs, outputs, and references. model_id
POST /scenario-engine/define Normalize realistic or worst-case incident definitions. incident_type, classification, inventory, equipment
POST /source-models/solve Compute release rate, total mass, and phase state. model_type, inputs
POST /dispersion-models/solve Compute screening concentration fields and threshold distances. gaussian_plume, gaussian_puff, dense_gas
POST /fire-explosion-models/solve Convert release or cloud energy into fire and blast hazards. jet_fire, pool_fire, fireball_bleve, tnt_equivalency, multi_energy, vce
POST /effect-models/solve Translate exposure into human impact with curves and population summaries. toxic_probit, toxic_dose_response, thermal_probit, thermal_dose_response, explosion_probit, explosion_dose_response
POST /toxic-criteria/lookup Lookup starter AEGL, ERPG, IDLH, TLV, PEL, and toxic-endpoint values. chemical, optional criteria_names, optional criteria_overrides
POST /prevention-response-models/solve Run ignition, inerting, spray/mist, prevention, and response planning screening models. fire_triangle_screening, autoignition_screening, inerting_requirement, ignition_energy_screening, spray_mist_screening, release_prevention_screening, emergency_response_planning
POST /signs/analyze Classify a sign from OCR text or manual text and return a leak-ready scenario seed. observed_text, optional image_base64, site_context
POST /visualization/solve Build plume maps, heatmaps, contours, and time-evolution payloads. layer_type, inputs
POST /gis/impact-zones Create map-ready impact circles for leak and fire scenarios. scenario_type, source, asset, criteria

Scenario Definition

Supports pipe_rupture, tank_leak, vessel_rupture, and relief_discharge with realistic_case and worst_case classifications. 

{
  "incident_type": "pipe_rupture",
  "classification": "worst_case",
  "inventory": { "mass_kg": 1000, "phase": "gas" },
  "equipment": { "diameter_m": 0.15 },
  "meteorology": { "wind_speed_m_s": 1.5, "stability_class": "F" }
}

Effect Models

Supports point estimates and dose-response curves, plus population distributions for expected case counts. 

{
  "model_type": "toxic_probit",
  "inputs": {
    "concentration_kg_m3": 0.12,
    "exposure_duration_s": 180,
    "population_distribution": [
      { "label": "Control Room", "population": 12, "concentration_kg_m3": 0.08, "exposure_duration_s": 240 }
    ]
          }
}

Sign Intelligence

Turn field signage into a scenario seed that downstream tools can consume immediately.

{
  "observed_text": "Warning Gas Pipeline Present High Pressure Gas",
  "site_context": "Buried line marker near road crossing",
  "stability_class": "D",
  "wind_speed_m_s": 3.0
}

Runtime Notes

Choose the runtime that fits your application boundary.

Browser-local: best for demos, GitHub Pages, embedded tools, and lightweight client-side evaluation.
HTTP API: best for shared services, audit trails, multi-user systems, notebooks, and agent infrastructures.
MCP server: best when you want tools and agents to call Deep Safety through a standard tool surface.
